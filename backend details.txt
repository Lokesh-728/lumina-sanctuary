# Database

## PostgreSQL

I wouldn't choose MongoDB for this project.

Manifestation apps have structured relationships:

* Users
* Journal Entries
* Daily Habits
* Habit History
* Goals
* Techniques
* Notifications
* AI Chats
* Vision Boards

Those are relational.

Postgres excels here.

---

# ORM

Prisma

Reasons

* Type-safe
* Easy migrations
* Great developer experience
* Excellent autocomplete
* Widely adopted

Example

```typescript
await prisma.user.findUnique({
    where: { id }
})
```

---

# Authentication

Use JWT.

Flow

```text
Login

↓

Access Token (15 min)

↓

Refresh Token (7–30 days)

↓

Renew automatically
```

Never store passwords yourself—store only securely hashed passwords (e.g. Argon2).

---

# Cache

Redis

Use Redis for

* Sessions
* Rate limiting
* OTP storage
* AI response caching
* Frequently accessed data
* Streak calculations

Without Redis

Everything hits the database.

---

# Queue System

BullMQ

For background jobs

Examples

* Daily reminders
* Email sending
* AI processing
* Weekly reports
* Push notifications
* Journal analysis

Never do these inside the API request.

Queue them.

---

# File Storage

Don't store images inside PostgreSQL.

Use

* Amazon S3
* Cloudflare R2
* Supabase Storage

Store only URLs in the database.

# Security Checklist

## Passwords

Use

Argon2

Never

SHA256

Never

MD5

---

## Validation

Validate

Every request.

NestJS + class-validator makes this straightforward.

Never trust frontend data.

---

## SQL Injection

Use Prisma.

Never

```sql
SELECT * FROM users WHERE email='${email}'
```

---

## XSS

Sanitize

* Journal entries
* Notes
* Comments
* AI prompts (where displayed)

---

## Rate Limiting

Prevent

```text
Login

10000 attempts
```

Use Redis-based rate limiting.

---

## CORS

Allow

Only

```text
https://yourdomain.com
```

Not

```text
*
```

---

## Helmet

Always use

Helmet

Security headers

Already solves many common attacks.

---

## HTTPS

Always.

No exceptions.

---

## CSRF

If using cookies

Protect against CSRF.

If using Authorization headers with JWT, the approach differs, but understand the trade-offs.
